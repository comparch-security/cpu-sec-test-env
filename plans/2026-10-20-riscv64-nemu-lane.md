- **`make ARCH=riscv64-nemu deploy`** → `scripts/riscv64_nemu/prepare.sh`: lane lock; preflights in one ordered block *before any build* (bench submodule at `BENCH_COMMIT` **and clean** — the cheap guard for a leak from the platform's registry swap; `NEMU_BIN` exists, is a regular file and executable; `git -C "$NEMU_DIR" rev-parse HEAD` equals the pinned `NEMU_COMMIT`, with a warning when that checkout is dirty); then the platform's `build-corpus.sh` and `build-image.sh` with `OUT="$ROOT/$BUILD_DIR/riscv64-nemu/platform"` (env-owned artifacts, so the lane's `clean` can `rm -rf` them and the submodule stays untouched apart from the transient swap), `RUNSET` (default `all`, validated against the platform's documented set; overridable for smoke), and this repo's pinned cross knobs (`CXX/CC/ASM/OBJDUMP/CROSS_COMPILE`, the env's riscv64 pins — the platform's own defaults, passed explicitly so env.sh stays the single source of truth); the two builders run supervised (see the coder's contract 1); on success it records the deployed runset in `$ROOT/$BUILD_DIR/riscv64-nemu/runset`, post-asserts the image and echoes the image + NEMU sha256s.
- **`make ARCH=riscv64-nemu run`** → `scripts/riscv64_nemu/run.sh` (modeled on `scripts/riscv64/run.sh`): lane lock; preflights before the trap — bench submodule at `BENCH_COMMIT` and clean, NEMU checkout at `NEMU_COMMIT`, `RUNSET` (defaulting to the recorded deployed runset, `all` when none) with a named mismatch when an explicit value disagrees with the deployed one, and the image at `$OUT/$RUNSET/fw_payload.bin` ("deploy first"); snapshot `$OUT/$RUNSET/runs/` (tolerating its absence), call the platform's `run.sh` under the lane's own bound (`LANE_RUN_TIMEOUT + 120 s` watchdog, `NEMU_TIMEOUT="$LANE_RUN_TIMEOUT"` forwarded so the platform diagnoses its own boot timeout first), supervised as in contract 1; require exactly one new run dir (naming candidates otherwise); on success compare the live `sha256sum "$NEMU_BIN"` against the run meta's `nemu_bin.sha256` and evaluate the completeness gate (the stamp's record set == the deployed runset's derived `$OUT/$RUNSET/configure.json` — identical to the tracked registry when `RUNSET=all`) **against the run dir, before copying any result file**; then collect into `results/riscv64-nemu/<stamp>/` — `results.json`, `results.dat`, `variables.json` (when produced), `boot.log`, `meta.json`, `meta.deploy.json` (the deploy/build meta: corpus compiler, input pins, image/rootfs sha256) — run `version_stamp.sh`, append the `# nemu` provenance section, and re-assert the submodule clean; the EXIT trap (contract 2) publishes the boot.log-only evidence stamp on non-timeout failures, publishes nothing on a timeout, always runs `make -C benchmark clean` and asserts the submodule clean.
- **Pins** (`env.sh`): `BENCH_COMMIT` → bench `a09f570` (the platform's commit; already pushed), the new NEMU block as a **relative** default — `: "${NEMU_DIR:=../NEMU}"`, `: "${NEMU_BIN:=$NEMU_DIR/build/riscv64-nemu-interpreter}"`, `NEMU_COMMIT=ae1ec3cd869b9c5e1783af691538d5c26f37ee55` (a plain, hard pin, like `BENCH_COMMIT`) — plus the exports; `NEMU_DIR`/`NEMU_BIN` are documented as a pair (a checkout elsewhere overrides both, absolute paths included; the lane scripts resolve relative values against the repo root). `version_stamp.sh`'s accepted-lane case gains `riscv64-nemu`.
- **No `derive_registry.py`**: `SKIP_TABLE` declares no `riscv64` row (the CHERI rows are the only skips), expectations live in the tracked registry, and the completeness gate compares against the deployed runset's derived registry — exactly the riscv64 lane's gate.

**First deploy** for the first cycle (Step 4) is seeded from the venue's own input-pinned caches in the submodule's `out/` (the three git checkouts, the kernel `Image` cache + `System.map`, busybox, OpenSBI, gcpt, the generated DTS — ~430 MB), so it runs **offline** in ~10 minutes; the corpus and the image are rebuilt from `a09f570` regardless. A cold deploy (network for the three checkouts; the kernel and busybox tarballs travel with the seeded `src` tree — `src/downloads/` under the lane's platform tree) remains the documented route and takes ~70–90 min (the kernel build alone ran ~1 h). After a deploy the lane runs offline; `clean` removes the caches with the build tree, like the riscv64 lane.

**Out of scope:** fixing F2 (the return-code-delivery workstream), the registry-swap scratch-tree redesign (its deferral), a uniform-pin all-lane re-run, per-class runset acceptance (the smoke use of `RUNSET` only), the platform's `run-native.sh` (venue-side tool; this cycle *consumes* its archived output as the comparison reference rather than re-running it). The bench-side venue README's "Not yet a lane" paragraph goes stale once this lands — a bench-repo cosmetic for the next bench cycle (recorded, not fixed here).
